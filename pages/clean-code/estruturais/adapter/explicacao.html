Clean Code / Design Pattern / Adapter

Explicação

Como encaixar uma interface que você não controla na interface que o seu código espera, sem espalhar a diferença pelo sistema inteiro.

O problema

O seu código já sabe o que quer: enviar(destino, texto). Aí entra um serviço de fora — uma SDK, uma API, uma biblioteca legada — que faz exatamente isso, mas com outro nome, outra ordem de argumentos e outro formato de retorno.

A saída preguiçosa é chamar o serviço direto, de dentro das regras de negócio:

antes — a diferença vaza para dentro
class AvisoDePedido:
    def confirmar(self, pedido):
        # a regra de negócio agora sabe o nome da SDK,
        # o formato do telefone e o código de retorno dela
        resp = twilio.messages.create(
            to="+55" + pedido.telefone,
            body=f"Pedido {pedido.id} confirmado",
        )
        if resp.status_code != 201:
            raise RuntimeError(resp.error_message)

Três coisas quebram daqui a pouco: trocar de provedor vira busca e substituição no projeto inteiro; testar exige a SDK de verdade; e a regra de negócio passa a ter um motivo a mais para mudar — exatamente o que o Single Responsibility pede para evitar.

A solução

Uma peça no meio, que fala as duas línguas. São sempre quatro papéis:

PapelQuem éNo exemplo
AlvoA interface que o seu código esperaNotificador
ClienteQuem usa o alvo, sem saber de mais nadaAvisoDePedido
AdaptadoO que já existe, com a interface erradaA SDK do provedor
AdaptadorImplementa o alvo e chama o adaptadoNotificadorTwilio

O ponto é a direção da dependência: quem define a interface é o seu lado, não o de fora. O adaptador é a única parte do sistema que conhece a SDK.

Implementação

from abc import ABC, abstractmethod

# 1. o alvo: a interface que o seu código escolheu
class Notificador(ABC):
    @abstractmethod
    def enviar(self, destino: str, texto: str) -> None: ...

# 2. o adaptador: traduz, e só
class NotificadorTwilio(Notificador):
    def __init__(self, sdk):
        self._sdk = sdk

    def enviar(self, destino, texto):
        resp = self._sdk.messages.create(to="+55" + destino, body=texto)
        if resp.status_code != 201:
            raise EnvioFalhou(resp.error_message)

# 3. o cliente: não conhece provedor nenhum
class AvisoDePedido:
    def __init__(self, notificador: Notificador):
        self._notificador = notificador

    def confirmar(self, pedido):
        self._notificador.enviar(pedido.telefone, f"Pedido {pedido.id} confirmado")
// 1. o alvo: a interface que o seu código escolheu
interface Notificador {
  enviar(destino: string, texto: string): Promise<void>;
}

// 2. o adaptador: traduz, e só
class NotificadorTwilio implements Notificador {
  constructor(private sdk: TwilioClient) {}

  async enviar(destino: string, texto: string) {
    const resp = await this.sdk.messages.create({ to: `+55${destino}`, body: texto });
    if (resp.statusCode !== 201) throw new EnvioFalhou(resp.errorMessage);
  }
}

// 3. o cliente: não conhece provedor nenhum
class AvisoDePedido {
  constructor(private notificador: Notificador) {}

  confirmar(pedido: Pedido) {
    return this.notificador.enviar(pedido.telefone, `Pedido ${pedido.id} confirmado`);
  }
}

O teste do cliente agora é uma classe de cinco linhas que implementa Notificador e guarda o que recebeu. Nenhuma rede, nenhum mock de biblioteca.

Quando usar

O Adapter vale quando três coisas acontecem ao mesmo tempo: já existe algo que faz o que você precisa, a interface dele não é a que o seu código quer, e mudar esse algo não é opção — porque é de terceiros, é legado ou é de outro time.

Na prática, isso aparece no código de algumas formas reconhecíveis:

SituaçãoComo reconhecer no códigoExemplo
Dependência externa no meio da regra de negócioimport de SDK em arquivo de domínio; o nome do fornecedor aparece dentro da regraUso #1
Dois fornecedores para a mesma operação, ou um segundo à vistaif gateway == "stripe" … elif …Uso #1
Legado ou código de outro time que você não pode alterarA mesma conversão de parâmetros e de retorno copiada em vários chamadoresUso #2
Dados de fora com os nomes e formatos de foraCampos do JSON externo (logradouro, localidade) em telas e regrasUso #3
Teste difícil por causa da infraestruturaPara rodar o teste é preciso credencial, rede ou um serviço falsoUso #4
Exceções de terceiros capturadas na regraexcept ClientError, códigos de erro do fornecedor comparados como stringUso #4
Estilo de chamada diferente do resto do códigoCallback no meio de async/await; laço de paginação repetidoUso #5, #6
Um framework pede uma interface específicaVocê quer "plugar" algo seu no logging, no storage, no ORMUso #7

Repare no que quase todos os sinais têm em comum: o nome de algo de fora aparece onde não deveria. O adaptador é o lugar para onde esse nome se muda — e de onde ele não sai mais.

Um teste rápido

Na dúvida, responda em ordem. A primeira resposta que manda parar decide.

  1. Já existe algo pronto que resolve? Se não, não há o que adaptar: escreva a classe direto, com a interface que você quer.
  2. A interface dele é diferente da que o seu código precisa? Se é praticamente a mesma, use direto.
  3. Você pode mudar a interface na origem? Se o código é seu e está ao alcance, mude lá. É mais simples que traduzir para sempre.
  4. A diferença vai aparecer em mais de um lugar, ou atrapalha testar? Se sim, é Adapter. Se é uma chamada isolada, em um lugar só, ainda dá para esperar.

Quando não usar

O Adapter tem um custo fixo, cobrado todo dia: um arquivo a mais, uma interface a mais e um salto a mais na leitura — o "ir para a definição" cai na interface, não no código que roda. Ele só se paga quando o que protege vale mais que isso.

SituaçãoPor que nãoFaça isto
Você controla os dois ladosO adaptador conserta uma diferença que você mesmo pode eliminarMude a interface na origem
Um fornecedor só, chamado em um lugar sóNão há diferença espalhada para conter; a camada só acrescenta leituraChame direto. Extraia o adaptador quando surgir o segundo uso ou o segundo fornecedor
Script, protótipo ou código descartávelO código vai embora antes de o custo se pagarChame direto
A interface alvo seria idêntica à da SDKNada é traduzido; o adaptador vira um repasseUse a SDK, ou redesenhe o alvo nos termos do seu domínio
Você quer simplificar um subsistema grandeO objetivo é reduzir a superfície, não converter uma interface em outraFacade
Você quer acrescentar cache, retry ou log mantendo a interfaceA interface antes e depois é a mesmaDecorator ou Proxy

Sinais de que o adaptador saiu do lugar

  • Ele toma decisões. Adaptador que valida regra de negócio, repete tentativas ou escolhe caminho deixou de traduzir. Isso é um serviço; dê a ele outro nome e outro lugar.
  • Os tipos do fornecedor vazam pelo retorno. Se cobrar() devolve um stripe.PaymentIntent, a interface parece sua, mas o cliente continua dependendo da SDK.
  • O cliente pergunta quem está do outro lado. Um isinstance(gateway, GatewayStripe) na regra mostra que a abstração não está segurando a diferença.
  • Adaptador sobre adaptador. Duas camadas traduzindo a mesma coisa: uma delas sobra.
  • Um adaptador para cada dependência, "por precaução". "Vai que um dia trocamos o banco" é abstração especulativa: o custo é cobrado hoje e o dia da troca talvez nunca chegue.

O sinal mais comum: a interface alvo cresceu até ficar igual à da SDK, campo por campo. Aí o adaptador não protege de nada — só adiciona um arquivo entre você e o erro.

Na dúvida, comece sem. Extrair um adaptador de uma chamada direta é uma refatoração pequena, principalmente se a chamada está em um lugar só. O que sai caro é deixar a SDK se espalhar por vinte arquivos antes de decidir.

Parecidos

PadrãoDiferença
FacadeSimplifica um subsistema inteiro; o Adapter converte uma interface em outra que já existia
DecoratorMantém a mesma interface e acrescenta comportamento; o Adapter muda a interface e não acrescenta nada
BridgeÉ desenhado antes, para abstração e implementação crescerem separadas; o Adapter entra depois, para consertar um encaixe
ProxyMesma interface, controlando o acesso (cache, permissão, preguiça)

Regra prática: se a interface antes e depois é a mesma, não é Adapter.
