DevMap

Meus estudos de programação, documentados em um só lugar: o que é este site, como ele está organizado e como eu escrevo nele.

O que é o DevMap

Um lugar só meu para registrar o que eu estudo de programação. Nasceu de um problema simples: anotação espalhada em editor de texto, favorito do navegador e print de tela não vira conhecimento. Escrever a mesma coisa em um formato fixo, com um lugar certo para ela morar, vira.

Não é blog nem portfólio. É material de consulta para mim mesmo, escrito no tom de quem explica para alguém que vai esquecer — porque esse alguém sou eu em três meses.

Áreas

Cada aba é um assunto grande. Cada página dentro dela é um recorte que cabe em uma leitura. Quando uma aba passar de umas dez páginas, as páginas entram em grupos no menu lateral.

Esta grade é montada a partir de assets/js/site.js. Ao registrar uma aba nova lá, o cartão aparece aqui sozinho.

Como eu escrevo uma página

Quatro regras, as mesmas em toda página:

  • Resumo obrigatório. Uma ou duas linhas abaixo do título dizendo o que a pessoa encontra. Se eu não consigo escrever o resumo, a página ainda não tem foco.
  • O problema antes da solução. Nenhuma técnica entra sem a situação que a justifica.
  • Código que roda. Exemplo curto, completo e testado. Nada de pseudocódigo com ... no meio.
  • Quando não usar. Toda página termina sabendo onde aquilo é má ideia.

Comece sempre por pages/_template.html. O template já vem com a moldura certa; sobra escrever o conteúdo.

Como este site funciona

São três partes: o mapa, a moldura e o conteúdo. O mapa fica em um arquivo só. A moldura é montada a partir dele. O conteúdo é a única coisa escrita à mão em cada página.

Criar uma aba

  1. Adicione um objeto em tabs, em assets/js/site.js.
  2. Crie a pasta pages/<id-da-aba>/.
  3. Crie a primeira página da aba, pelo passo abaixo.
assets/js/site.js
{
  id: 'algoritmos',                // vira a pasta pages/algoritmos/
  label: 'Algoritmos',             // o texto da aba
  icon: 'bolt',                    // window.DS.icons lista todos
  summary: 'Complexidade, ordenação e busca.',
  pages: [
    // uma página solta
    { id: 'overview', label: 'Overview', summary: 'Por onde começar.' },

    // uma sessão: só um título no menu, não é pasta
    { group: 'Ordenação', pages: [

      // uma pasta: vira pasta de verdade em pages/algoritmos/quicksort/
      { folder: 'quicksort', label: 'Quicksort', pages: [
        { id: 'explicacao', label: 'Explicação', summary: 'Dividir, particionar, repetir.' }
      ]}
    ]}
  ]
}

Criar uma página

  1. Adicione o nó da página em site.js, no lugar certo da árvore.
  2. Copie pages/_template.html para o caminho correspondente.
  3. No <body>, ajuste data-tab, data-page e data-root.
  4. Troque o <title>, a categoria, o título e o resumo.
  5. Escreva o conteúdo dentro de .prose.

O data-page é o caminho dentro da aba, sem .html, e o data-root é o caminho de volta até a raiz — um ../ por nível:

Arquivodata-pagedata-root
pages/clean-code/overview.htmloverview../../
pages/clean-code/adapter/explicacao.htmladapter/explicacao../../../

Uma página que existe mas não está no site.js abre pelo endereço direto e funciona, só não aparece no menu, na busca nem na paginação. Registre sempre.

Em que estado isto está

Esta é a primeira versão: a estrutura de base, montada para receber conteúdo. O que já funciona:

  • Abas, menu lateral e paginação gerados do mapa do site
  • Busca por página com Ctrl K ou /
  • Índice da página montado a partir dos títulos
  • Tema claro e escuro, com a escolha guardada no navegador

As páginas de conteúdo de verdade vêm depois. Por enquanto, a única aba tem só a sua visão geral.

Design

O visual é o mesmo do BetterAI: os tokens, os componentes e as regras estão em Design System. A única diferença é que aqui não existe seletor de idioma — o DevMap é só em português.

Não escreva cor, raio ou fonte dentro de uma página. Tudo vem das variáveis de assets/css/tokens.css. Para mudar o visual, mude o token — nunca o CSS de uma página.
